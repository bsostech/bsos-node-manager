# Web UI

The web UI of BSOS Node Manager is built with React, TypeScript and Vite. It talks to the platform only through the
Platform API defined in `../contract/openapi.yaml` (base path `/api/v1`). The production build is embedded into the
server binary and served from the same origin as the API.

## Development

The build needs Node.js 22 and npm. Install dependencies with `npm ci`; `.npmrc` disables dependency install
scripts.

```bash
npm ci
npm run dev        # http://localhost:5173
npm run dev:core   # same, but treats src/enterprise/ as absent to show the Core edition
```

The dev server always runs against mock data. `src/main.tsx` starts [MSW](https://mswjs.io) in dev mode, and the
handlers in `src/mocks/` answer every `/api/v1` request; there is no proxy to a real backend. The login page shows
the demo accounts and a switch between two demo scenarios, `existing` (an established deployment) and `fresh` (a new
install with no registered nodes). The scenario can also be set with `?demo=existing` or `?demo=fresh`.

`dev:core` affects only the dev server. A production build includes the Enterprise UI when `src/enterprise/` exists
and leaves it out otherwise.

## Build and checks

```bash
npm run gen:api     # regenerate src/api/types.ts from ../contract/openapi.yaml (and the Enterprise types if present)
npm run typecheck
npm run build       # tsc -b && vite build, output in dist/
```

Run `gen:api` after any contract change and commit the generated types with it; CI fails when they differ. There is
no unit test suite. CI runs `npm run build`, which type-checks through `tsc -b`; `npm run typecheck` runs the same
check without bundling. The type check also fails when an error `reason`
in the contract has no message in `src/i18n/zh.json` or `src/i18n/en.json`.

To run the UI against a real platform, build the platform image from `backend/Dockerfile`. Its first stage runs
`npm run build`, and the Go stage embeds `dist/` through `backend/internal/webapp`.

## Layout

| Path | Contents |
|---|---|
| `src/api/` | Contract types (`types.ts`, generated), fetch client, schema aliases |
| `src/auth/` | Session context and role permissions |
| `src/pages/` | One component per route (routes are declared in `src/App.tsx`) |
| `src/components/` | Shared UI components |
| `src/hooks/`, `src/lib/` | Data hooks, formatting, status and threshold logic |
| `src/i18n/` | Traditional Chinese and English strings |
| `src/theme/` | Brand tokens, CSS variables, light and dark themes |
| `src/mocks/` | MSW handlers, fixtures and demo scenarios (dev only) |
| `src/runbook/` | Node onboarding runbook templates, generated by `tools/runbook/` |
| `src/edition.ts`, `src/enterprise/` | Edition seam; `src/enterprise/` is the Enterprise edition and is not part of the public export |
| `public/` | MSW service worker, brand assets |

The sidebar is defined in `src/nav.ts`. Each route checks the user's permission in the browser; the backend
enforces the same permissions.
